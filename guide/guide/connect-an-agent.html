Connect an agent ​

An agent is an AI assistant that runs in another app on your computer, such as Claude Desktop, Claude Code, Codex, Cursor or Gemini CLI. Connected to Leathercase, it can read your stories the way Leathercase reads them (their scenes, characters, threads, grid, boards and logs) and, if you allow it, leave findings and propose changes that wait for you in the inbox. This page explains what an agent can and cannot do through Leathercase, how to connect each kind of client, and how to watch, pause and revoke agents.

Only you write your prose: no agent can, through Leathercase or its editor. No tool an agent can call takes a path on your computer, none runs a command, and none writes your files.

Before you connect: what Leathercase does not control ​

Read this first. The app shows the same warning, word for word, every time you connect an agent or widen what it may see.

Leathercase governs only what passes through it. It does not govern anything else your agent can do.

Many agents can also run commands on your computer, open any file you can open, or browse the web. Connecting such an agent to your stories gives it your stories beside everything it could already reach. Leathercase cannot see those other tools and cannot stop them. If your agent can read your files, it can read your manuscript without asking Leathercase.

So grant an agent only the writing homes you mean to share, and read what your agent's own tools allow before you connect it. Only Leathercase's own assistant, the mate, is bounded entirely by Leathercase.

WARNING

Pausing or revoking an agent in Leathercase stops what it does through Leathercase. It does not stop the agent's app from doing anything else it was already able to do.

How it works ​

Leathercase is the server, and it must be running for an agent to reach your stories. Your agent's app starts a small bridge program, leathercase-mcp, which finds Leathercase on this computer and passes every message to it over a local connection, with no open network port.

  • When Leathercase is closed, the bridge opens it in the background, without taking focus. The title bar then says, for example, "Opened for Claude Desktop at 14:02".
  • When Leathercase is not installed, the agent is told where to download it.
  • When you quit Leathercase, the agent's next requests are told Leathercase is not running. When you open it again, the bridge picks up the session by itself; you do not need to restart the agent's app.
  • Leathercase stays open when the agent leaves. It is your app.

Each agent you connect gets its own id (such as claude-desktop or codex) and its own token, a secret kept in a file in the app's data on this computer. The token is what identifies the agent. The name an agent's app reports about itself is shown to you but never trusted.

The bridge speaks the Model Context Protocol (MCP), the open standard most agent apps use to reach tools.

What an agent can see and do ​

What an agent may do depends on its grant: which writing homes it may read, and which toolsets it holds. You set the grant when you connect it and can change it at any time.

Homes ​

An agent sees only the writing homes you tick, with every story in them, including stories you add there later. Asked about any other home, it is told the home is not shared. It never sees a folder path.

What an agent is for ​

An agent helps you lay out your story's views; it never writes the story. With a story already drafted, it reads what you wrote and sets up the plot grid, the beat board and the rest, so you start from a laid-out desk instead of an empty one. With a story just begun, talk it over with the agent and it builds the views as you plan: columns, themes and arcs, the rows to come. Some of the structure has to come from you.

Asked to write a story, a scene or its prose, an agent connected to Leathercase is told to say no and to offer the structure instead. A cell, a card or a summary it proposes says what happens in a line or two, never the scene itself, and it is marked as generated.

Toolsets ​

ToolsetIn SettingsWhat the agent may do
ReadAlways onRead stories, scenes and their prose, names, the plot grid, the threads, the graph, the beat board, the writer board and tags, comments, counts, logs and progress, and when each scene last changed; search the stories; ask what you are looking at; show you a view or a scene
AssistOff until you turn it onAlso leave findings and comments beside your scenes, and propose comments, threads and facts. Nothing changes until you accept it in the inbox
Lay outOff until you turn it onAlso propose how your beat board, plot grid and Graph are laid out: new and moved cards, planned rows, row summaries, columns with their kind and a line about them, filled cells, ties and tabs with their roles, and how unsorted files of a story should be read. Nothing changes until you accept it in the inbox, and what it laid out is marked as generated until you edit it

Turning Lay out on turns Assist on with it, because laying out proposes through the assistant's tools. Turning Assist off turns Lay out off. Lay out was called Author until October 2026; an agent granted Author keeps the grant as Lay out.

Every proposal from an agent is a changeset that waits in the inbox. You accept it whole, item by item, or after editing an item; or you dismiss it. Only your accept writes anything, and what it writes is Leathercase's own files (your board, your grid file, your comments), never your manuscript. See Proposals and the inbox.

Which scene you worked on last ​

Ask an agent "what was the last scene I worked on?" and it can answer. Each time Leathercase reads your story it notes which scenes changed and by how many words, including what you changed while Leathercase was closed. The agent says how it knows:

  • from Leathercase's own record, when Leathercase saw the scene change; for a change made while Leathercase was closed, it says the change came some time after Leathercase last read the story;
  • from the chapter file's date, for work from before Leathercase first read your story. That date is the file's, so any scene in the file, or copying or syncing it, may have set it, and the agent says so.

"The last scene" can also mean the one that ends the story. The agent is given both and answers both, or asks which you mean.

The record starts the first time Leathercase reads a story; what you wrote before is in the word counts but on no day. It is kept as plain lines in the story's suite/logs/writing/ folder.

What an agent can do in the window ​

An agent with any grant can ask what you are looking at in Leathercase (the home, the story, the view and the selected scene), but only when that home is one it was granted. It can also ask Leathercase to show you a story's view or a scene in the manuscript. Showing is never writing: the window goes there, as a find would, and the breadcrumb follows.

What an agent can never do ​

These hold whatever the grant says:

  • run a program or a command, or reach the network through Leathercase;
  • name a path; everything is addressed by the ids Leathercase gives (home, story, scene, card);
  • read outside the folders of its granted homes, even through a shortcut or a link on disk;
  • write your manuscript or your own notes;
  • change your board, grid or comments without your accept;
  • treat the text of your stories as instructions: Leathercase hands it over as data.

An agent that tries to leave its homes is refused, the refusal is logged and shown to you, and Leathercase may pause that agent by itself (see Paused by Leathercase).

What the agent learns about Leathercase ​

Leathercase also serves its in-app guide pages and six short skill packs to any agent, so an agent can learn how Leathercase reads a story without you explaining it: how to start (homes, stories, ids, the kinds of file), story structure, the story views, the writer board and tags, logs and progress, and how to propose well. They teach what the views are; they carry no storytelling prompts. An agent brings its own.

Connecting an agent ​

Open Settings › Agents (Ctrl+,, or Cmd+, on macOS, then Agents) and press Connect an agent. The Connect page shows its three steps at once, with a summary beside them.

  1. Client. The program that will call Leathercase. Pick one of Claude Desktop, Cowork, Codex, Claude Code, Cursor or Gemini CLI. Claude Desktop and Cowork say "one click · .mcpb": Leathercase hands them a bundle to install. The others say "config to copy": Leathercase shows you a line to add to the client's settings.
  2. Name. What this agent is called in the list, its log and the title bar. It starts as the client's name. Under it, the id Leathercase makes from the name, for example "id: claude-desktop". If an agent with that id already exists, it says "connecting again replaces its token".
  3. Grant. Tick the Writing homes it may read, and the Toolsets it may use. If you have a single home, it is ticked for you.

Beside the steps, What this grant allows says plainly, as you change them, what the agent can read, which homes it cannot see, whether it can change anything, that every call is written to its log for 90 days, and "Whatever it can do outside Leathercase, it still can."

Under the steps is the warning, Before you connect. Then Connect, Cancel, and Read the guide: Connect an agent, which opens the in-app guide page with every client's setup; Back to Connect returns.

Connect makes the agent's token at once. What happens next depends on the client.

Claude Desktop and Cowork ​

  1. Pick Claude Desktop (or Cowork), tick the homes, and press Connect.
  2. Leathercase opens its bundle, leathercase.mcpb, in Claude Desktop. The page says "The bundle is open in Claude Desktop. Accept it there; then ask Claude Desktop about your stories." On Linux, where no Claude app opens .mcpb files, Leathercase shows the bundle in your file manager instead, and the page says to install it from Claude Desktop's Settings, Extensions.
  3. In Claude Desktop, accept the install. Leathercase appears among its connectors.
  4. Leave the agent id in the bundle's settings as claude-desktop, unless you connected it under another name.

If the bundle cannot be opened, the page says why and points you to the guide, which says how to add it by hand.

Claude Code ​

Connect Claude Code in Leathercase first; it gets the id claude-code. The page then shows "Add this to Claude Code, then restart it:" and the line to run in a terminal, with a Copy button:

claude mcp add --transport stdio --scope user leathercase -- npx -y leathercase-mcp --agent claude-code

The line names the agent, never its token: "no token in it: the bridge reads it on this computer".

Codex ​

Connect Codex first; it gets the id codex. Then, from a terminal:

codex mcp add leathercase -- npx -y leathercase-mcp --agent codex

Or add it to ~/.codex/config.toml by hand:

[mcp_servers.leathercase]
command = "npx"
args = ["-y", "leathercase-mcp", "--agent", "codex"]

Cursor ​

Connect Cursor first; it gets the id cursor. Then add this to ~/.cursor/mcp.json, or to .cursor/mcp.json in one project:

{
  "mcpServers": {
    "leathercase": {
      "command": "npx",
      "args": ["-y", "leathercase-mcp", "--agent", "cursor"]
    }
  }
}

Gemini CLI ​

Connect Gemini CLI first; it gets the id gemini-cli. Then add this to ~/.gemini/settings.json:

{
  "mcpServers": {
    "leathercase": {
      "command": "npx",
      "args": ["-y", "leathercase-mcp", "--agent", "gemini-cli"]
    }
  }
}

If you gave the agent another name, its id differs, and the line Leathercase shows you already carries that id. Copy it from Leathercase rather than from this page.

Press Done to return to the list.

Agents connected before 0.30 ​

Leathercase took its new name in 0.30, and with it a new bridge, leathercase-mcp. Agents you connected before keep their homes, toolsets and logs, but each one still starts the old bridge, which no longer answers. Until you say it is done, Settings › Agents shows a box above the list, Your agents need the new bridge:

  • For Claude Desktop or Cowork, install the bundle again: Connect an agent, pick the client, tick its homes and press Connect.
  • For the others, connect again and replace the old command in the client's settings with the line the Connect page shows.

Done puts the box away.

Other clients and ChatGPT ​

Any other client that speaks MCP over a local program can use the same bridge: connect it in Leathercase under a name of your choice, then give the client the command npx -y leathercase-mcp --agent followed by its id.

ChatGPT cannot connect for now: it reaches only servers on the internet, and Leathercase will not relay your stories through one.

Then ask ​

Once connected, ask your agent about your stories in its own window, for example "In Leathercase, which scenes of The Lamp at Ferrol have no point of view?" The agent works in its own app; Leathercase shows you who is connected and what it is reading.

The agents list ​

Settings › Agents lists the programs on this computer that read your stories through Leathercase, each with its own token, grant and log. A line above the table sums it up, for example "1 connected · 1 calling now · 2 refused this week · 1 revoked". In the navigation, Agents shows how many are connected, and an amber dot when there are refusals you have not seen.

With no agent, it says "No agent is connected. Connect one to let it read the homes you choose, through Leathercase."

Each agent's row shows:

ColumnWhat it shows
AgentIts name; a small ring when its bridge is running now; the client it reports about itself in quotes, in amber when that differs from what it first reported
ToolsetsWhat it holds, such as "read · assist · layout"
HomesThe homes it may read, or "no home"
SinceWhen you connected it
Last callThe time, the tool and what it was about, or "no calls yet"; refusals not yet seen in amber; "paused by Leathercase" when it was

Under each row:

  • Log opens the agent's log (see The agent log).
  • Edit grant opens the homes and toolsets in place. A home or toolset you add is marked "added" and brings the warning back. Save grant applies from the agent's next call; Cancel leaves it as it was.
  • Revoke ends the agent at once. Its next call is refused. Its row moves to Revoked · N, folded at the foot, which says, for example, "Codex, revoked 6 Oct · its log is kept until 4 Jan", with its Log. To use it again, connect it again.

At the foot, a note: "The name is yours. What a client reports about itself is shown, never trusted: the token is what identifies it." and the Pause all agents button (Resume all agents while paused).

The indicator in the title bar ​

While an agent's bridge is running, or while you have paused agents, a small rounded indicator sits in the title bar. It says what is happening in words, never by colour alone:

After the words, in amber: "· 1 refused" for refusals you have not seen, and "· Codex paused" when Leathercase paused an agent by itself. With no bridge running and nothing paused, the indicator is not shown at all.

Leathercase never shows a pop-up, a sound or a system notification for agents. The indicator is the whole of it.

The agents menu ​

Click the indicator to open its menu:

  • Each agent, with its last call ("last call 14:06 · get_scene") or the call running now, and any refusals not yet seen, said in words, for example "1 refused: Journal is not shared". A log › link opens its log.
  • An agent Leathercase paused shows "Paused by Leathercase after trying to leave its homes" and a Resume link.
  • Pause all agents, "refuses every call until you resume"; while paused, Resume all agents.
  • Inbox, with how many changesets wait to be reviewed.
  • Preferences › Agents, with its key.

Opening the menu counts as seeing the refusals: the amber count leaves the title bar, while the menu still lists what they were. Esc closes the menu.

Refusals ​

When Leathercase turns a call away, the agent is told why, and you see the reason in the indicator, the menu and the log:

Leathercase saysWhy

Paused by Leathercase ​

Every attempt to reach a file outside the granted homes is refused. An agent that tries five times within a minute is also paused by Leathercase, so every later call is refused too until you look. Its row says "paused by Leathercase", the indicator adds "· Codex paused", and the menu offers Resume for that agent. Read its log before you resume it.

The agent log ​

Every call an agent makes is written to its log, kept 90 days, even after you revoke the agent. Open it with Log in Settings › Agents or log › in the agents menu. ‹ Agents goes back.

At the top, the agent's name and a summary: calls since when, how many refused, how many words of your text it read, and what its client reports. Then:

  • Show: All, Refused · N or Lay out · N (its proposals to the board, the grid and the Graph).
  • Home and Story menus narrow it to one home or story ("every home", "every story").
  • "kept 90 days", and Export…, which saves every call of the agent as a file of one JSON object per line, for you to keep.

The calls are grouped by day, newest first ("Today · Tuesday 6 October", "Yesterday · …"), each day with its totals: calls, refusals and words read. Words read is how much of your prose left the app that day.

Each line gives the time, the tool, what it was about (story › scene), and how it ended: "ok", "ok · 238 words", "refused ·" and the reason, or "failed ·" and a code. A call of the Lay out toolset ends "proposed: waits in the inbox for your word", and these lines are set off with a dashed line. Click a refused call to open it: It asked for (the tool and its arguments), It was told (the code and the reason), and What left Leathercase: nothing. Show more loads older calls.

The logs live with your stories, in suite/logs/assistant/ in each story's folder and in the home's own suite/logs/ for calls about the whole home, so they travel with the home (see Files Leathercase writes). A call about a home the agent was not granted is never written into that home: it is kept in this computer's own agent log, in the app's data, and shown on the agent's log page with the others, naming the home it asked for.

When something goes wrong ​

  • The agent says Leathercase is not running. Open Leathercase once, then ask again. If it is not installed, the message says where to download it.
  • The agent says it is not connected. Connect it in Leathercase under the id its settings use.
  • The agent says its token was refused. You revoked it, or connected it again since. Connect it again in Leathercase.
  • The agent says a home is not shared. Tick that home with Edit grant; it applies from the next call.
  • The agent cannot propose anything. Turn on Assist, or Lay out for the board, the grid and the Graph, with Edit grant.
  • Calls are refused with "paused by you". You paused all agents: Resume all agents in the agents menu or in Settings › Agents.
